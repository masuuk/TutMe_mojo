Calling Python from Mojo, calling Mojo from Python, C-ABI interop with native libraries, and MLIR integration.

Mojo ↔ Python: Seamless Interop

One of Mojo's strongest features is its native Python interoperability. You can import any Python module directly from Mojo, pass values back and forth, and even call Python functions inside Mojo kernels. The Mojo runtime embeds CPython, so every package in the Python ecosystem is immediately available.

Mojo
Python
# Import Python modules directly
from python import Python

def main() raises:
    # Use numpy from within Mojo
    var np = Python.import_module("numpy")
    var arr = np.array([1, 2, 3, 4, 5])
    var mean_val = np.mean(arr)
    print("NumPy mean:", mean_val)

    # Use matplotlib
    var plt = Python.import_module("matplotlib.pyplot")
    plt.plot(arr)
    plt.savefig("plot.png")
    plt.show()

    # Use pandas
    var pd = Python.import_module("pandas")
    var df = pd.DataFrame({"a": [1,2], "b": [3,4]})
    print(df.describe())

💡 Key insight:

Python objects in Mojo are dynamically typed. You can pass them to Mojo functions, but you lose compile-time type safety. For best performance, convert Python data to native Mojo types (like Tensor or NDArray) at the boundary.

Calling Python from Mojo: Advanced Patterns

You can wrap entire Python ML pipelines in Mojo, use Python objects in Mojo control flow, and even define Python callbacks that are invoked from compiled Mojo code.

Mojo
from python import Python, PythonObject

def train_sklearn_model() raises:
    # scikit-learn inside Mojo
    var sklearn = Python.import_module("sklearn.linear_model")
    var np = Python.import_module("numpy")

    # Prepare data
    var X = np.array([[1],[2],[3],[4]])
    var y = np.array([2, 4, 6, 8])

    # Train model
    var model = sklearn.LinearRegression()
    model.fit(X, y)

    # Predict from Mojo
    var pred = model.predict(np.array([[5]]))
    print("Prediction for 5:", pred)

# Pass Mojo data to Python via buffer protocol
def mojo_to_numpy():
    var np = Python.import_module("numpy")
    var data = List[Float64]()
    for i in range(100):
        data.append(Float64(i) * 0.1)

    # Convert List to numpy array via Python
    var arr = np.array(data)
    print(arr.shape)

C-ABI Interop: Calling Native Libraries

Mojo can call any library that exposes a C-compatible ABI — C, C++, Fortran, and any other language that can compile to a C ABI. You bind native functions with extern declarations and link against the shared library (.so / .dll / .dylib). This is how Mojo reaches the vast ecosystem of high-performance numerical and systems libraries.

Mojo
C (shared lib)
from std.memory import Layout, dealloc
# Declare the external C functions
def c_add(a: Int32, b: Int32) -> Int32
    "libc_math".add

def c_sort(ptr: Pointer[Int32], length: Int32)
    "libc_math".sort_in_place

def main():
    # Call native functions directly
    var result = c_add(21, 21)
    print("C says:", result)  # 42

    # Pass Mojo pointers to native code
    var allocation = alloc(Layout[Int32](count=5))
    var buf = allocation.unsafe_ptr()
    buf[0] = 5; buf[1] = 3; buf[2] = 1; buf[3] = 4; buf[4] = 2
    c_sort(buf, 5)
    print(buf[0], buf[1], buf[2], buf[3], buf[4])  # 1 2 3 4 5
    dealloc(allocation^)
// C side: libc_math.c
int add(int a, int b) {
    return a + b;
}

void sort_in_place(int *ptr, int len) {
    for (int i = 1; i < len; i++) {
        int key = ptr[i];
        int j = i - 1;
        while (j >= 0 && ptr[j] > key) {
            ptr[j + 1] = ptr[j];
            j--;
        }
        ptr[j + 1] = key;
    }
}
C-ABI compatibility

The same mechanism works for any language that compiles to a C-compatible ABI. Use extern declarations in Mojo to bind any native function — from BLAS to custom CUDA kernels. Mojo's cc compiler can also link .so / .dll files directly.

MLIR: The Foundation of Mojo

Mojo compiles to MLIR (Multi-Level Intermediate Representation), which means it can target any hardware that MLIR supports — CPUs, GPUs, TPUs, and custom accelerators. You can even embed MLIR dialects directly in Mojo code for fine-grained hardware control.

Mojo
# Mojo compiles to MLIR under the hood
# The compiler pipeline:
#   Mojo source → Mojo IR → MLIR (standard + GPU + LLVM dialects) → LLVM IR → Machine code

# You can target specific hardware via MLIR attributes
def gpu_kernel(ctx: DeviceContext):
    # Mojo automatically maps to the GPU dialects
    ctx.enqueue_function[work](grid_dim=1, block_dim=1024)
    # Each thread runs one iteration of the work function

# This compiles to:
#   gpu.launch_func @kernel blocks=(1,1,1) threads=(1024,1,1)
# Which the GPU backend lowers to PTX / Metal / SPIR-V

# Cross-compilation targets
# mojo build --target aarch64-apple-darwin    # Apple Silicon
# mojo build --target x86_64-unknown-linux    # Linux x86
# mojo build --target nvptx64-nvidia-cuda     # NVIDIA GPU
Why MLIR matters for DS/ML

MLIR lets Mojo compile the same source code to different backends. A function written once can run on a CPU for prototyping, then be compiled to GPU for production — with zero code changes. This is the "write once, run everywhere" promise applied to hardware acceleration.
