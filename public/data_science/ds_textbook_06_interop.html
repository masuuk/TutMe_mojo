🤝 The Python Interop Bridge

Mojo's killer feature for data scientists: call any Python library directly from Mojo, use NumPy and pandas in Mojo code, and expose Mojo functions back to Python — all with zero-copy type mapping.

Calling Python from Mojo

Mojo embeds a CPython interpreter. This means you can import and call any Python module directly from Mojo code, with automatic type conversion for common types. You do not need wrappers, bindings, or FFI declarations. Just import and call.

python_interop.mojo
native_python.py
# Mojo — call Python directly
from python import Python

# Import any Python module
var os = Python.import_module("os")
var sys = Python.import_module("sys")
print(os.getcwd())           # works!
print(sys.version)           # Python version string

# Call Python functions
var math = Python.import_module("math")
var pi = math.pi
var root = math.sqrt(144.0)
print(root)                  # 12.0

# Use Python's json module
var json = Python.import_module("json")
var data = json.loads('{"name": "Mojo", "version": 1}')
print(data["name"])        # Mojo

# Python exceptions become Mojo errors
try:
    var result = json.loads("not json")
except e:
    print(f"Python error: {e}")
# Python — the native version
import os
import sys
import math
import json

print(os.getcwd())
print(sys.version)

pi = math.pi
root = math.sqrt(144.0)
print(root)

data = json.loads('{"name": "Mojo", "version": 1}')
print(data["name"])

Mojo's Python interop is built-in — no wrappers, no external build configuration, no manual GIL management.

The GIL situation

Mojo runs Python code through the embedded CPython interpreter, which means the Global Interpreter Lock (GIL) still applies to Python calls. The benefit is that Mojo's own code runs outside the GIL at full native speed. The strategy: do your hot loops in Mojo, call Python for ecosystem access (file I/O, visualization, data loading).

Using NumPy, pandas, and scikit-learn from Mojo

The real power of Python interop is using the vast Python data science ecosystem from Mojo code. You can load data with pandas, manipulate it with NumPy, and train models with scikit-learn — all while writing Mojo for the performance-critical parts.

using Python data science libraries from Mojo
# Import the Python data science stack
var np = Python.import_module("numpy")
var pd = Python.import_module("pandas")
var plt = Python.import_module("matplotlib.pyplot")

# Load a CSV with pandas
var df = pd.read_csv("data/housing.csv")
print(df.head())
print(df.shape)

# Convert to NumPy for computation
var features = df[["sqft", "beds", "baths"]].to_numpy()
var target = df["price"].to_numpy()

# Use scikit-learn for quick ML
var sklearn = Python.import_module("sklearn.linear_model")
var model = sklearn.LinearRegression()
model.fit(features, target)
print(model.score(features, target))

# Plot with matplotlib
plt.scatter(features[Python.Slice(0, None), 0], target)
plt.xlabel("Square Feet")
plt.ylabel("Price")
plt.savefig("scatter.png")
When to use Python vs native Mojo

Use Python interop for: data loading (pandas, CSV readers), visualization (matplotlib, seaborn), pre-built ML models (scikit-learn, HuggingFace), and anything where ecosystem breadth matters more than raw speed.

Use native Mojo for: custom training loops, tensor operations, SIMD-optimized kernels, real-time inference, and any code path that runs millions of times per second.

Calling Mojo from Python

The interop bridge works both ways. You can write performance-critical functions in Mojo and call them from Python using the mojo module. This lets you keep your existing Python data pipeline while replacing the slow parts with Mojo.

fast_kernel.mojo
use_mojo.py
# Mojo — export functions for Python
from python import Python
from python import PythonObject

# Define a fast function
def fast_normalize(
    data: Tensor[DType.float32]
) -> Tensor[DType.float32]:
    var mean = data.reduce_add() / Float32(data.num_elements())
    var result = data - mean
    var std = sqrt((result * result).reduce_add()
                  / Float32(data.num_elements()))
    return result / std

# Mojo can also expose a Python module
def register():
    var mojo_module = Python.import_module("mojo_fast")
    mojo_module.normalize = fast_normalize
# Python — call Mojo from Python
import numpy as np
from mojo_fast import normalize

# Generate data
data = np.random.randn(1000000).astype(np.float32)

# Call the Mojo function — runs at native speed
normalized = normalize(data)
print(normalized.mean(), normalized.std())

# This is 10-100x faster than a pure Python
# normalize function, because Mojo compiles
# the inner loop to native SIMD instructions

This is the incremental adoption story: keep your Python pipeline, replace slow functions one at a time with Mojo.

Type mapping between Mojo and Python

When you cross the Python-Mojo boundary, types are automatically converted. Understanding the mapping helps you write efficient interop code and avoid surprises.

Mojo TypePython TypeNotes
IntintAutomatic, zero-cost for small values
Float64floatAutomatic conversion
StringstrAutomatic, copies the string data
BoolboolAutomatic
List[Int]list[int]Converts element-wise
Dict[String, Int]dictConverts keys and values
Tensor[DType.float32]numpy.ndarrayShares memory when possible
PythonObjectAny Python objectOpaque handle, call methods on it
type conversion examples
# Mojo — type conversions at the boundary
var np = Python.import_module("numpy")

# NumPy array → Mojo Tensor (shares memory!)
var py_array = np.array([1.0, 2.0, 3.0], dtype=np.float32)
var tensor = Tensor[DType.float32](py_array)

# Mojo Tensor → NumPy array
var mojo_tensor = Tensor[DType.float32]([4.0, 5.0, 6.0])
var back_to_python = mojo_tensor.to_numpy()

# PythonObject for opaque handles
var pd = Python.import_module("pandas")
var df: PythonObject = pd.read_csv("data.csv")
var shape = df.shape  # Python tuple, access as PythonObject
print(shape[0], shape[1])

# Passing lists across the boundary
var py_list = Python.list()
py_list.append(42)
py_list.append("hello")
print(Python.len(py_list))  # 2
🚚 Zero-copy tensor transfer

When you convert a NumPy array to a Mojo Tensor (or vice versa), Mojo attempts to share the underlying memory rather than copying. This means you can load data with NumPy, pass it to Mojo for fast processing, and get results back — all without allocating extra memory. This is critical for large ML datasets.

As of Mojo 1.0 final

Interop got two significant upgrades. First, PythonObject arithmetic, comparison, and membership operators now dispatch through CPython's abstract protocols (PyNumber_Add, PyObject_RichCompare, ...) instead of a Python-level attribute lookup plus bound-method call — roughly 12x faster on the interop hot path, with standard Python semantics including reflected operands (__radd__ et al). Second, the new std.python.numpy module provides copy_to_numpy_array() (copies a Mojo Span/List into a fresh NumPy array) and from_numpy_array() (borrows the array's buffer zero-copy) for all fixed-width numeric dtypes — no more hand-written ctypes plumbing:

from std.python.numpy import from_numpy_array, copy_to_numpy_array

var np = Python.import_module("numpy")
var py_array = np.arange(1_000_000, dtype=np.float32)
var view = from_numpy_array(py_array)   # Span[Float32], zero-copy
var fresh = copy_to_numpy_array(view)      # independent NumPy array
