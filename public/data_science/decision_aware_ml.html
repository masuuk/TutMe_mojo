1. The Objective, Formally

Every page below is a variation on one setup: features x, an uncertain quantity y, a predictor fθ(x) = ŷ, and an optimizer that turns the prediction into a decision. Learn these four equations; everything else is code.

(1) pipeline:  d(ŷ) = arg mind ∈ D c(d; ŷ)
(2) task loss:  ℓtask(ŷ, y) = c( d(ŷ); y )   — piecewise-constant in ŷ
(3) regret vs perfect information:  Regret(θ) = E[ c(d(fθ(x)); y) − c(d(y); y) ]
(4) surrogate training objective:  minθ (1/n) Σ ℓsurrogate(fθ(xi), yi) + λ·R(θ)

Equation (2) is why this field exists: d(·) is an arg min, so the task loss is piecewise-constant — its gradient is zero almost everywhere and uninformative at the jumps. You cannot backprop through it directly. Sections 2–4 avoid the problem by changing the target (quantile, threshold, weights); Sections 5–6 fix it by surrogate losses that have real gradients.

The one intuition: a prediction error only costs money when it changes d(ŷ). Decision-aware learning spends model capacity exactly on those errors — in deployment (Sierra Leone medicines) this meant weighting under-stocked facilities 8–10× in the loss, and raised actual medicine consumption by 19%.

2. Newsvendor & the Critical Fractile

The hello-world of decision-aware ML. Order q before seeing demand D; overage costs co per unsold unit, underage costs cu per unmet one.

E[cost(q, D)] = co·E[(q − D)+] + cu·E[(D − q)+]  where  (t)+ = max(t, 0)
first-order condition:  P(D ≤ q*) = cu / (cu + co)
∴ q* = F−1( cu / (cu + co) )   — the critical fractile quantile

Decision-awareness in one closed form: the costs do not change the forecast — they change which quantile of the forecast you act on. An MSE model predicts the mean and answers the wrong question whenever cu ≠ co.

import numpy as np

c_u, c_o = 8.0, 1.0              # stockout is 8x worse than overage
fractile = c_u / (c_u + c_o)          # 0.888…

hist = np.random.lognormal(3.0, 0.6, size=200)
q_mse = hist.mean()                   # wrong target: the mean
q_da  = np.quantile(hist, fractile)   # cost-aware target: the quantile

def cost(q, d):
    return c_o*np.maximum(q-d, 0) + c_u*np.maximum(d-q, 0)

test = np.random.lognormal(3.0, 0.6, size=10_000)
print(cost(q_mse, test).mean(), cost(q_da, test).mean())  # quantile wins big

In Mojo the empirical quantile is visibly what it is — sort, index at the fractile — and the whole experiment (sample → quantile → evaluate on millions of draws) compiles to one pass with no interpreter in the loop:

from collections import List
from random import random_float64, seed
from math import sqrt, log, cos, exp, PI

def lognormal(mu: Float64, sigma: Float64, n: Int) -> List[Float64]:
    var xs = List[Float64]()
    for _ in range(n):                # Box–Muller
        var u1 = random_float64(1e-12, 1.0)
        var u2 = random_float64(0.0, 1.0)
        var z = sqrt(-2.0*log(u1)) * cos(2.0*PI*u2)
        xs.append(exp(mu + sigma*z))
    return xs

def quantile(xs: List[Float64], q: Float64) -> Float64:
    xs.sort()                          # empirical quantile = sorted index
    return xs[Int(q * Float64(len(xs)-1) + 0.5)]

def cost(q: Float64, d: Float64, c_u: Float64,
             c_o: Float64) -> Float64:
    return c_o*max(q-d, 0.0) + c_u*max(d-q, 0.0)

def main():
    seed(42)
    var c_u: Float64 = 8.0
    var c_o: Float64 = 1.0
    var fr = c_u / (c_u + c_o)
    var hist = lognormal(3.0, 0.6, 200)
    var q_da = quantile(hist, fr)         # cost-aware order
    var test = lognormal(3.0, 0.6, 1_000_000)
    var tot: Float64 = 0.0
    for d in test:
        tot += cost(q_da, d, c_u, c_o)
    print("expected cost:", tot / 1e6)

3. Cost-Optimal Classification Threshold

Same idea for classifiers: with asymmetric error costs, the operating threshold is not 0.5 — it falls out of the cost ratio. For a binary problem with predicted probability p = P(y=1|x):

predict positive iff  p · cFN > (1 − p) · cFP
⟹  threshold  τ* = cFP / (cFP + cFN)
expected cost of decision (1,0):  (1−p)·cFP  ·  decision (0,1):  p·cFN  — pick the smaller

Triage example: sending a severe patient home costs 8, escalating a mild one costs 1.5, so τ* = 1.5 / 9.5 ≈ 0.158 — escalate anyone with >16% severe risk.

import numpy as np

C = np.array([[0.0, 8.0],      # C[true, pred]: [0,1] severe→home
              [1.5, 0.0]])     #               [1,0] mild→escalate

c_fp, c_fn = C[1, 0], C[0, 1]
tau = c_fp / (c_fp + c_fn)            # 0.158 — not 0.5!

def decide(p):                 # p = calibrated P(severe)
    return (p > tau).astype(int)

expected_cost = np.mean(C[y_true, decide(p_pred)])  # the metric to report
from collections import List

def threshold(c_fp: Float64, c_fn: Float64) -> Float64:
    return c_fp / (c_fp + c_fn)

def decide(p: List[Float64], tau: Float64) -> List[Int]:
    var out = List[Int](capacity=len(p))
    for i in range(len(p)):
        out[i] = 1 if p[i] > tau else 0
    return out

def decision_cost(C: List[Float64],       # flattened 2×2
                    y: List[Int], d: List[Int]) -> Float64:
    var total: Float64 = 0.0
    for i in range(len(y)):
        total += C[y[i]*2 + d[i]]       # C[y, d]
    return total / Float64(len(y))

4. Impact Reweighting

The simplest decision-aware training change, and what was actually deployed for medicine allocation: keep the off-the-shelf model, weight the loss by decision impact. It is the first-order Taylor approximation of the decision loss (Chung et al., ML4H 2022):

ℓweighted(θ) = (1/n) Σi wi · ( fθ(xi) − yi )²   with  wi ∝ ∂(decision cost) / ∂(prediction error at i)

For stock allocation the impact weight is the unmet-demand exposure: facilities likely to run out of stock get up-weighted, exactly the Sierra Leone design.

import numpy as np

def decision_weights(hist_demand, stock, c_u):
    cover = np.clip(stock / (hist_demand + 1e-9), 0, 1)
    impact = c_u * (1 - cover)         # unmet-demand proxy
    return impact / impact.sum()      # weights sum to 1

# then: model.fit(x, y, sample_weight=w)   — any sklearn/GBM model
from tensor import Tensor

def decision_weights(hist: Tensor[DType.float64],
                     stock: Tensor[DType.float64],
                     c_u: Float64) -> Tensor[DType.float64]:
    var n = hist.num_elements()
    var impact = Tensor[DType.float64](n)
    for i in range(n):
        var cover = stock[i] / (hist[i] + 1e-9)
        cover = min(max(cover, 0.0), 1.0)   # clip to [0,1]
        impact[i] = c_u * (1.0 - cover)
    return impact / impact.reduce_add()   # weights sum to 1

# weights computed in Mojo, consumed in Python:
#   model.fit(x, y, sample_weight=weights.to_numpy())
The weighting kernel is pure arithmetic over contiguous memory — that is Mojo's half of the job. Training stays in the Python ecosystem via the interop bridge.

5. The SPO+ Loss

Impact reweighting is a first-order fix. The SPO+ loss (Elmachtoub & Grigas, "Smart Predict, then Optimize") is a genuine convex surrogate for the regret, valid for linear objectives c(d; y) = yᵀd over a polyhedral feasible set:

ℓSPO+(ŷ, y) = maxd ∈ D [ yᵀd − 2ŷᵀd ] + mind ∈ D yᵀd

= c(d(−y); y) − 2·c(d(ŷ); y) + c(d(y); y)   (worst-case − twice-your − optimal)

ℓSPO+ ≥ Regret(ŷ, y)  always;  convex in ŷ;  exact surrogation for the LP case

Read it as: take the decision that is worst under the true costs but attractive under your forecast, and charge yourself its true cost, credited by what your forecast's decision and the oracle decision would have cost. Convex in ŷ — so it plugs into gradient training. Canonical example: shortest path with predicted edge costs.

import numpy as np
from scipy.sparse.csgraph import shortest_path

# graph with TRUE edge costs y; model predicts y_hat
def path_cost(adj, y):
    # cost of the shortest path under y (decision = argmin path)
    _, pred = shortest_path(adj, directed=True,
                            return_predecessors=True)
    return pred  # path structure — see note below

def spo_plus(y, y_hat, D):
    # D = callable: c -> decision d(c) minimizing c^T d
    c_hat  = y_hat @ D(y_hat)       # cost of YOUR decision
    c_orac = y @ D(y)               # cost of oracle decision
    c_worst = max(y @ d - 2*(y_hat @ d) for d in D.extreme_points())
    return c_worst - 2*c_hat + c_orac

# training loop: theta -= lr * grad(spo_plus(f(x), y))
# SPO+ for the 1-D allocation case: D = [0, q_max], c(d; y) = -y*d
# (buy d units, earn y per unit). d(c) = q_max if c > 0 else 0.

def d_of(c: Float64, q_max: Float64) -> Float64:
    return q_max if c > 0.0 else 0.0

def spo_plus_1d(y: Float64, y_hat: Float64,
                    q_max: Float64) -> Float64:
    var c_your = -(y * d_of(y_hat, q_max))     # c(d(y_hat); y)
    var c_orac = -(y * d_of(y,      q_max))     # c(d(y); y)
    # worst-case over D = {0, q_max}: pick the max of the two corners
    var g0 = y*0.0  - 2.0*y_hat*0.0
    var g1 = y*q_max - 2.0*y_hat*q_max
    return max(g0, g1) - 2.0*c_your + c_orac

# piecewise-linear in y_hat → subgradient exists everywhere;
# train with a subgradient step per sample.

Alternatives at a glance: DSL smooths the decision loss with a bandwidth h → 0 (robust under misspecification); perturbed optimizers (next section) randomize instead. SPO+ needs the LP structure; perturbation needs only a solver you can call k times.

6. Perturbed-Optimizer Gradients

General recipe when you cannot write the arg min analytically: add random noise, average, differentiate the average. Randomized smoothing of the optimizer gives a differentiable map with a Monte-Carlo gradient estimator:

d̃ε,μ(ŷ) = EZ[ d(ŷ + εZ) ],  Z ~ N(0, Σ)

∇ŷ d̃ ≈ (1/k) Σj d(ŷ + εZj) · Zjᵀ / ε   (used inside the chain rule for ∇θ)

Cost k optimizer solves per training step — a throughput problem, i.e. exactly the workload where the Mojo version of the inner loop pays for itself.

import numpy as np

def perturbed_decision_and_grad(y_hat, solver, eps=0.1, k=64):
    Z = np.random.normal(size=(k, len(y_hat)))
    d_bar = np.zeros_like(y_hat)
    grad  = np.zeros_like(y_hat)
    for z in Z:
        d_j = solver(y_hat + eps*z)      # one optimizer solve
        d_bar += d_j
        grad  += np.outer(d_j, z) / eps  # accumulate grad estimate
    return d_bar / k, grad / k

# theta -= lr * (d-bar Jacobian) @ grad  — plug into autograd manually
from collections import List
from random import normal_float64, seed
from math import sqrt

def perturbed_grad(y_hat: List[Float64],
                     solve: SolverFn, eps: Float64,
                     k: Int) -> List[Float64]:
    var n = len(y_hat)
    var grad = List[Float64](n, 0.0)
    for j in range(k):
        var z = List[Float64](n)
        for i in range(n):
            z[i] = normal_float64()
        var noisy = List[Float64](n)
        for i in range(n):
            noisy[i] = y_hat[i] + eps * z[i]
        var d_j = solve(noisy)         # one optimizer solve
        for i in range(n):
            grad[i] += d_j[i] * z[i] / eps
    for i in range(n):
        grad[i] /= Float64(k)
    return grad

# k solves per step × millions of steps — batch them and the
# compiled loop is the difference between a day and an hour.

7. SAA & In-Sample Optimism

Sample Average Approximation — OR's workhorse — plus the bias that breaks it in the small-data regime, and the correction:

SAA:  mind E[c(d; Z)]  →  mind (1/n) Σi c(d; Zi)

optimism:  E[ in-sample objective ] < true objective,  bias ≈ p/n  (p ≈ effective # of fit parameters)
cross-validation does not remove it — every fold re-optimises on training data (non-vanishing bias)

VGC debiasing:  Ĉout = Ĉin + (∂ Ĉin / ∂ Zᵢ)ᵀ ΣZ (∂ Ĉin / ∂ Zᵢ) · (1/n)  — smooth in policy parameters, usable for selection, not just evaluation 
import numpy as np

# 1) see the optimism yourself: SAA newsvendor on tiny samples
def saa_order(samples, c_u, c_o):
    return np.quantile(samples, c_u/(c_u+c_o))

rng = np.random.default_rng(0)
true_opt = []  in_sample = []
for _ in range(500):
    train = rng.lognormal(3.0, 0.6, 30)   # n = 30 only
    q = saa_order(train, 8.0, 1.0)
    in_sample.append(cost(q, train).mean())   # looks great…
    test = rng.lognormal(3.0, 0.6, 10_000)
    true_opt.append(cost(q, test).mean())     # …but this is the truth
print(np.mean(in_sample), np.mean(true_opt))  # gap = the bias
# 2) VGC-style bootstrap debias, 1-D newsvendor:
#    perturb the sample, re-solve, measure sensitivity.
def vgc_debias(samples: List[Float64],
                   c_u: Float64, c_o: Float64,
                   delta: Float64) -> Float64:
    var q0 = quantile(samples, c_u/(c_u+c_o))
    var n = len(samples)
    var bias: Float64 = 0.0
    for i in range(n):
        samples[i] += delta              # perturb one sample
        var q1 = quantile(samples, c_u/(c_u+c_o))
        samples[i] -= delta              # restore
        # dC/dZ_i ≈ Δobjective / Δsample; accumulate squared sensitivities
        bias += (cost(q1, samples[i], c_u, c_o)
               - cost(q0, samples[i], c_u, c_o)) ** 2
    return bias * delta / Float64(n) / 2.0

# debiased estimate = in-sample cost + vgc_debias(...)

Small-data, large-scale regime: ~37 monthly observations per facility, thousands of facility–product pairs. Every estimate is noisy; every optimizer overfits its sample. The toolkit: multi-task pooling, catalytic priors toward a population baseline, impact weighting (Section 4), and VGC debiasing before you trust any comparison.

8. Decision-Aware Evaluation

One loop, three numbers — mean decision cost, per-component cost, and worst-group cost (equity). AUC never appears.

def evaluate_decisions(C, y_true, y_pred, groups):
    cost = C[y_true, y_pred]
    print("mean cost     :", cost.mean())
    for g in np.unique(groups):
        m = groups == g
        print(f"  group {g}: cost={cost[m].mean():.3f}")
    print("worst group   :",
          max(cost[groups==g].mean() for g in np.unique(groups)))
# deployed causal claims → randomized rollout + difference-in-differences,
# as in the Sierra Leone evaluation (+19% consumption, p < 0.01).
def mean_decision_cost(C: Tensor[DType.float64],
                          y: List[Int],
                          d: List[Int]) -> Float64:
    var total: Float64 = 0.0
    for i in range(len(y)):
        total += C[y[i], d[i]]
    return total / Float64(len(y))

# worst-group: same loop over per-group index lists, keep the max.
# One compiled pass = mean + components + equity for a million rows.

9. Cost-Weighted LLM Fine-Tuning

When the decision-maker is a fine-tuned LLM, decision-awareness means the loss weights and the reward carry the cost matrix — not the token loss. Mechanics (LoRA/QLoRA) are in the companion tutorial.

weighted SFT loss:  L(θ) = − Σi wi · log Pθ(responsei | prompti)   with  wi = expected decision impact of example i

RLHF/DPO reward:  r(output) = − E[ decision cost of the action parsed from output ] 
# triage assistant, QLoRA fine-tune with decision weights
c_fp, c_fn = 1.5, 8.0

def example_weight(p_severe):
    # impact of an error on this example, from the cost matrix
    return p_severe*c_fn + (1-p_severe)*c_fp

# SFTTrainer(..., ) then:
# trainer = WeightedSFTTrainer(weights=[example_weight(p) for p in probs])
# evaluate: mean decision cost (Section 8), never accuracy alone
def example_weight(p_severe: Float64,
                     c_fp: Float64, c_fn: Float64) -> Float64:
    return p_severe*c_fn + (1.0 - p_severe)*c_fp

# weights for 1M training rows: one compiled pass, shipped to the
# Python trainer as a NumPy array across the interop bridge.
