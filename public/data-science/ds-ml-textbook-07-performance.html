⚡ Performance Optimization

Vectorization, SIMD, parallelization, and profiling — squeezing every cycle out of your Mojo code.

Loop Vectorization

The single most impactful optimization for numerical code is vectorization: replacing scalar operations with wide SIMD (Single Instruction, Multiple Data) operations that process 4, 8, or 16 elements simultaneously. Mojo's compiler can automatically vectorize simple loops, but understanding how to guide it gives you control over performance.

In Python, NumPy handles vectorization behind the scenes by dispatching to C. In Mojo, SIMD is a first-class citizen with language-level support, so you can write vectorized code directly.

from math import sqrt

def dot_product_simd(
    a: Tensor[Float32], b: Tensor[Float32]
) -> Float32:
    var n = a.num_elements()
    var total: Float32 = 0.0
    var i = 0
    # Process 8 elements at a time with SIMD
    comptime S = simdwidthof[Float32]()  # typically 8
    var simd_acc = SIMD[Float32, S](0.0)
    while i + S <= n:
        simd_acc += a.load[0](i) * b.load[0](i)
        i += S
    # Horizontal reduction
    for k in range(S):
        total += simd_acc[k]
    # Handle remainder
    while i < n:
        total += a[i] * b[i]
        i += 1
    return total
import numpy as np

def dot_product(a, b) -> float:
    # NumPy dispatches to SIMD-optimized BLAS
    return np.dot(a, b)

# Or with explicit SIMD via numba:
from numba import njit, prange

@njit(parallel=True)
def dot_product_numba(a, b):
    var total = 0.0
    for i in prange(len(a)):
        total += a[i] * b[i]
    return total
💡 Key Insight:

Mojos SIMD[Float32, S] type is a compile-time fixed-width vector. The compiler knows exactly how many elements it holds, so it can map directly to AVX2/AVX-512 instructions without any runtime dispatch.

Working with SIMD Intrinsics

Mojo provides low-level access to SIMD operations through its SIMD type. This gives you the same control as C intrinsics but with safe, ergonomic syntax. Common operations include element-wise math, reductions, and shuffles.

from math import sqrt

def softmax_simd(mut logits: Tensor[Float32]):
    var n = logits.num_elements()
    # Find max for numerical stability
    var max_val: Float32 = logits[0]
    for i in range(1, n):
        if logits[i] > max_val:
            max_val = logits[i]

    # Vectorized exp using SIMD
    comptime S = simdwidthof[Float32]()
    var exp_sum: Float32 = 0.0
    var max_vec = SIMD[Float32, S](max_val)
    var i = 0
    while i + S <= n:
        var v = logits.load[0](i) - max_vec
        var ev = exp(v)
        logits.store(i, ev)
        exp_sum += ev.reduce_add()
        i += S
    # Scalar remainder
    while i < n:
        var e = exp(logits[i] - max_val)
        logits[i] = e
        exp_sum += e
        i += 1
    # Normalize
    var inv_sum = 1.0 / exp_sum
    i = 0
    while i + S <= n:
        logits.store(i, logits.load[0](i) * inv_sum)
        i += S
    while i < n:
        logits[i] *= inv_sum
        i += 1
# In Python, you'd typically use NumPy or write C extensions
# with intrinsics like _mm256_fmadd_ps for AVX2 FMA

# Python equivalent (scalar, no SIMD):
import math

def softmax(logits):
    max_val = max(logits)
    exps = [math.exp(x - max_val) for x in logits]
    total = sum(exps)
    return [e / total for e in exps]
🚀 Pro Tip:

Mojos load and store methods on Tensor use aligned memory access when possible. Aligned loads are significantly faster on x86 — up to 2x throughput for large arrays.

Parallelization with Threads

Once your inner loops are vectorized, the next step is parallelization: splitting work across multiple CPU cores. Mojo provides a parallelize function that handles thread pool management automatically.

from algorithm import parallelize

def parallel_matmul(
    A: Tensor[Float32],
    B: Tensor[Float32],
    C: Tensor[Float32],
):
    var M = A.shape()[0]
    var N = B.shape()[1]
    var K = A.shape()[1]

    # Parallelize over rows
    def compute_row(row: Int):
        for j in range(N):
            var acc: Float32 = 0.0
            for k in range(K):
                acc += A[row, k] * B[k, j]
            C[row, j] = acc

    parallelize[compute_row](M, num_cores=logical_cores())
from multiprocessing import Pool
import numpy as np

def parallel_matmul(A, B):
    # NumPy already parallelizes via BLAS
    return A @ B

# Manual parallelism (slower due to GIL):
def compute_row(args):
    row, A, B = args
    return np.dot(A[row], B)

with Pool() as p:
    results = p.map(compute_row,
        [(i, A, B) for i in range(A.shape[0])])
💡 Key Insight:

Mojos parallelize[fn](total_items, num_cores) abstracts thread pool management. Unlike Python's multiprocessing, it uses lightweight threads that share memory — no pickling overhead, no process startup cost.

Memory Management and Layout

Performance isn't just about speed — it's about memory access patterns. A cache-friendly data layout can be 10x faster than a naive one, even with the same algorithm. Mojo gives you control over allocation strategy, memory layout, and copy semantics.

Stack vs Heap Allocation

Mojo's Tensor with compile-time-known dimensions can be stack-allocated. Small tensors (up to a few KB) should live on the stack to avoid heap allocation overhead.

from memory import memcpy, stack_allocation

# Small fixed-size buffer on the stack
def compute_with_stack_buf(
    input: Tensor[Float32]
) -> Float32:
    # 256 floats = 1KB on stack, no malloc
    comptime BUF_SIZE = 256
    var buf = stack_allocation[Float32, BUF_SIZE]()

    # Copy input into stack buffer
    var n = min(input.num_elements(), BUF_SIZE)
    memcpy(buf, input.data(), n)

    # Process on stack — cache-friendly
    var total: Float32 = 0.0
    for i in range(n):
        total += buf[i] * buf[i]
    return sqrt(total)
# Python relies on the OS allocator
# and cannot control stack allocation
import numpy as np

def compute(input_arr):
    # Always heap-allocated
    buf = np.zeros(256, dtype=np.float32)
    buf[:len(input_arr)] = input_arr[:256]
    return np.sqrt(np.sum(buf ** 2))
⚠️ Watch Out:

Mojos stack_allocation is for fixed-size, compile-time-known sizes only. For dynamic sizes, you'll use the heap. Profile before optimizing — premature stack allocation can actually hurt if it causes stack overflow on large inputs.

Profiling and Benchmarking

You can't optimize what you can't measure. Mojo integrates with standard profiling tools and provides built-in benchmarking primitives. The key is to profile on realistic data sizes and focus on the hottest code paths.

from time import now

def benchmark():
    var N = 1000000
    var A = Tensor[Float32](N)
    var B = Tensor[Float32](N)
    # Initialize with random data
    for i in range(N):
        A[i] = randn_float32()
        B[i] = randn_float32()

    # Time the dot product
    var start = now()
    var result = dot_product_simd(A, B)
    var elapsed = now() - start
    print("Result:", result)
    print("Time:", elapsed / 1e6, "ms")

import time
import numpy as np

def benchmark():
    N = 1_000_000
    A = np.random.randn(N).astype(np.float32)
    B = np.random.randn(N).astype(np.float32)

    start = time.perf_counter()
    result = np.dot(A, B)
    elapsed = time.perf_counter() - start
    print(f"Result: {result}")
    print(f"Time: {elapsed*1000:.2f}ms")
