Drill 12 · Errors & Context Managers

Handle failure with typed errors as values, and manage resources with `with`.

Your task

Define a custom typed error: `struct ValidationError(Copyable, Writable)` with `var field: String` and `var reason: String` using `@fieldwise_init`. Write `def validate_username(username: String) raises -> String` that raises `ValidationError` when empty. Catch it in `main` with `try/except` and print both fields. Then implement a `with` context manager for a temporary "file" that tracks `__enter__`/`__exit__`.

Based on Chapter 10 · Errors & Context Managers. Do the problem before looking for a solution or answering the checkpoint. If you forget syntax, use the Mojo Library.

Checkpoint · multiple choice

What must a Mojo 1.0 function do if it can fail?

Why: `raises` is the explicit contract: it tells the compiler (and callers) that the function may raise, so the caller must handle it with `try`/`except`.
Solution

Reference code: a custom typed error, `raises`, try/except, and a context manager.

@fieldwise_init
struct ValidationError(Copyable, Writable):
    var field: String
    var reason: String

def validate_username(username: String) raises -> String:
    if len(username) == 0:
        raise ValidationError("username", "cannot be empty")
    return username

def main():
    try:
        validate_username("")
    except err as ValidationError:
        print(err.field)   # username
        print(err.reason)  # cannot be empty

    # A minimal context manager: CM tracks enter/exit
    with CM() as f:
        f.write("hello")   # --body--
    # after the with block: exit already ran
