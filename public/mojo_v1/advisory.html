📐 The Speedup Math

Before any code: the two formulas that decide whether porting a kernel is worth it.

Amdahl's law — parallel/accelerated fraction f of runtime, speedup n on that fraction:

S(n) = 1 / ( (1 − f) + f/n )

Worked example — kernel is 80% of runtime (f = 0.8), Mojo makes it 40× faster:
S = 1 / (0.2 + 0.8/40) = 1 / 0.22 ≈ 4.5× overall — even though the kernel itself flew.

Roofline check (is the kernel compute- or memory-bound?)

attainable FLOP/s = min( peak FLOP/s,
                     bandwidth × I )

I = FLOPs / bytes — arithmetic intensity

Low I (streaming, e.g. axpy) → memory-bound: SIMD won't help much, layout will. High I (matmul inner loop) → compute-bound: this is where Mojo's SIMD types pay off.

Monte Carlo error shrinks slowly

SE( x̄ ) = σ / √N

100× fewer error → 10,000× more samples

This is why Monte Carlo is the canonical Mojo win: the algorithm cannot be made smarter — only faster per sample. 100× per-sample speed = 10× less error for the same wall-clock.

🎛️ Structs, Traits, comptime

The three Mojo concepts with no exact Python counterpart — each in one screen.

🔥 Mojo — generic norm over any dtype, resolved at compile time 
trait Squarable:
    def square(self) -> Self

struct Vec2[T: Squarable]:
    var x: T
    var y: T

    def norm2(self) -> T:
        return self.x.square() + self.y.square()

# comptime: computed during compilation, zero runtime cost
comptime N = 1024
comptime LANES = simdwidthof[DType.float64]()  # 4 or 8, per CPU

def main():
    var v = Vec2[Float64](3.0, 4.0)
    print(v.norm2())      # 25.0
    print(N, LANES)

What to remember

  • struct = stack-allocated value type (copy semantics), unlike Python's heap classes.
  • trait ≈ Protocol / ABC, but checked at compile time.
  • alias → comptime, @parameter loops and compile-time if/for = generics fully resolved before the code runs — the C++ template power, with Python spelling.

Ownership in one line each

  • arg: T — read-only reference (the default).
  • mut arg: T — mutable reference.
  • var arg: T — owned copy; transfer at the call site with ^.
  • Returning big tensors → return by value; Mojo elides the copy.

⚡ Dot Product & SIMD

⟨a, b⟩ = Σᵢ aᵢbᵢ   ·   cosine similarity = ⟨a,b⟩ / (‖a‖‖b‖)   ·   ‖a‖ = √⟨a, a⟩
🐍 Python (NumPy — already vectorized) 
import numpy as np

def dot(a, b):
    return np.dot(a, b)

def cosine(a, b):
    return np.dot(a, b) / (
        np.linalg.norm(a) * np.linalg.norm(b))
🔥 Mojo — explicit SIMD lanes 
from math import sqrt

def dot(a: Pointer[Float64],
        b: Pointer[Float64],
        n: Int) -> Float64:
    comptime LANES = simdwidthof[DType.float64]()
    var acc = SIMD[DType.float64, LANES](0)
    @parameter
    for i in range(n // LANES):
        acc += a.simd_load[LANES](i * LANES) \
             * b.simd_load[LANES](i * LANES)
    var total = acc.reduce_add()
    # scalar tail
    for i in range(n // LANES * LANES, n):
        total += a[i] * b[i]
    return total

def norm(a: Pointer[Float64], n: Int) -> Float64:
    return sqrt(dot(a, a, n))

Why the Mojo version can beat NumPy here: the loop is unrolled at compile time (@parameter), lanes are chosen per CPU (simdwidthof), and there is no dispatch overhead — the machine executes one fused multiply-add per lane per cycle.

🧮 Matrix Multiplication

C = AB:   Cij = Σₖ AikBkj   ·   cost = O(n³) multiply-adds = 2n³ FLOPs   ·   arithmetic intensity I = 2n³ / (3n² × 8 bytes) ≈ n/12
🐍 Python — triple loop (the hotspot to kill) 
def matmul(A, B, n):
    C = [[0.0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            s = 0.0
            for k in range(n):
                s += A[i][k] * B[k][j]
            C[i][j] = s
    return C

# fast version: delegate to BLAS
# C = A @ B   (numpy)
🔥 Mojo — tiled kernel sketch 
def matmul(A: Tensor[Float64], B: Tensor[Float64])
           -> Tensor[Float64]:
    var n = A.dim(0)
    var C = Tensor[Float64](n, n)
    # tile rows/cols; for full machine utilization, take the
    # tiles to a GPU via max.gpu DeviceContext.enqueue_function
    for ti in range(0, n, 64):
        for tj in range(0, n, 64):
            var tile = heap_allocation_blocked  # 64×64 block
            for i in range(ti, ti+64):
                for k in range(n):
                    var a = A[i, k]
                    for j in range(tj, tj+64):
                        tile[i, j] += a * B[k, j]
            # write tile back to C
    return C

Why tiling works — the cache equation

working set per tile = 3 × 64² × 8 B = 96 KB < L2

The naive loop re-reads B's column n times (cache-hostile, stride-n access). Tiling keeps a 64×64 block hot in cache; that single change is often worth 5–10× before SIMD even starts.

The i-k-j reorder (zero-cost win)

Loop order i,k,j walks B row-wise and C row-wise — all sequential memory. Identical FLOPs, dramatically fewer cache misses. Try it in both languages; it speeds up the Python triple loop too.

🖥️ Convolution Filter (the raster/kernel primitive)

out(x, y) = Σi Σj w(i, j) · in(x + i − r, y + j − r)   (kernel size K = 2r + 1)

cost = H · W · K² · (2 ops)  ·  separable kernel (Gaussian!): K² → 2K passes
🐍 Python (SciPy) 
from scipy.signal import convolve2d

def blur(img, k):
    return convolve2d(img, k, mode="same",
                      boundary="symm")

# separable Gaussian: much cheaper
def gaussian_blur(img, k1d):
    tmp = convolve2d(img, k1d[:, None],
                     mode="same")
    return convolve2d(tmp, k1d[None, :],
                      mode="same")
🔥 Mojo — boundary-checked kernel loop 
def convolve(img: Tensor[Float64],
             w: Tensor[Float64])  # K×K, K odd
             -> Tensor[Float64]:
    var H = img.dim(0); var W = img.dim(1)
    var K = w.dim(0); var r = K // 2
    var out = Tensor[Float64](H, W)
    # rows are independent — parallelize across y on a GPU
    # (max.gpu) or with multiple threads
    for y in range(H):
        @parameter
        for x in range(W):
            var acc = 0.0
            for i in range(K):
                for j in range(K):
                    var yy = min(max(y+i-r, 0), H-1)
                    var xx = min(max(x+j-r, 0), W-1)
                    acc += w[i, j] * img[yy, xx]
            out[y, x] = acc
    return out

This exact loop is NDVI smoothing, slope/aspect, edge detection and CNN layers — one kernel shape, every domain.

📉 Gradient Descent

update rule:   θ ← θ − η ∇J(θ)

linear regression:   J(θ) = (1/2m) Σ (h(x⁽ⁱ⁾) − y⁽ⁱ⁾)²,   h(x) = θᵀx
gradient:   ∇J = (1/m) Xᵀ(Xθ − y)  ·   closed form:   θ = (XᵀX)⁻¹Xᵀy
🐍 Python 
import numpy as np

def gd(X, y, eta=0.01, iters=1000):
    m, n = X.shape
    theta = np.zeros(n)
    for _ in range(iters):
        grad = X.T @ (X @ theta - y) / m
        theta -= eta * grad
    return theta
🔥 Mojo 
def gd(X: Tensor[Float64], y: Tensor[Float64])
       -> Tensor[Float64]:
    var m = X.dim(0).to_float64()   # samples
    var n = X.dim(1)                # features
    var theta = Tensor[Float64](n)  # starts at 0
    var resid = Tensor[Float64](X.dim(0))
    for it in range(1000):
        # resid = X·theta − y  (prediction error)
        matvec(X, theta, resid)
        @parameter
        for i in range(resid.num_elements()):
            resid[i] -= y[i]
        # grad = Xᵀ·resid / m ; theta −= η·grad
        vecmat(X, resid, theta, 0.01 / m)
    return theta

Variants to know (same update shape, different η schedule)

momentum:  v ← βv + ∇J,  θ ← θ − ηv   ·   RMSProp:  s ← γs + (1−γ)(∇J)²,  θ ← θ − η∇J/√(s+ε)   ·   Adam = momentum + RMSProp

🎲 Monte Carlo (π, and option pricing)

π̂ = 4 · (hits / N)   with hits = #{(uᵢ, vᵢ) : uᵢ² + vᵢ² ≤ 1}
European call (Black–Scholes, risk-neutral):  C ≈ e^(−rT) · (1/N) Σ max(S·exp((r − σ²/2)T + σ√T·zᵢ) − K, 0),  zᵢ ~ N(0,1)

error:  SE = σ/√N — every 100× speedup buys one extra decimal digit
🐍 Python 
import numpy as np

def pi_mc(n, rng):
    u = rng.random(n)
    v = rng.random(n)
    return 4.0 * np.mean(u*u + v*v <= 1.0)

def call_mc(S, K, r, sigma, T, n, rng):
    z = rng.standard_normal(n)
    ST = S * np.exp((r - sigma**2/2)*T
                    + sigma*np.sqrt(T)*z)
    payoff = np.maximum(ST - K, 0.0)
    return np.exp(-r*T) * payoff.mean()
🔥 Mojo 
from math import sqrt, exp

def pi_mc(n: Int, seed: UInt64) -> Float64:
    var rng = Random(seed)
    var hits = 0
    # embarrassingly parallel: every sample is independent,
    # so each thread can own its own rng and counter
    for i in range(n):
        var u = rng.random_float64()   # uniform in [0,1)
        var v = rng.random_float64()
        if u*u + v*v <= 1.0:           # inside quarter circle?
            hits += 1
    return 4.0 * hits.to_float64() / n.to_float64()

def call_mc(S: Float64, K: Float64, r: Float64,
            sigma: Float64, T: Float64,
            n: Int) -> Float64:
    var rng = Random(42)
    var acc = 0.0
    for i in range(n):
        var z = rng.normal_float64()   # z ~ N(0,1)
        # risk-neutral terminal price S_T
        var ST = S * exp((r - sigma**2/2)*T
                         + sigma*sqrt(T)*z)
        acc += max(ST - K, 0.0)        # discounted later
    return exp(-r*T) * acc / n.to_float64()

Monte Carlo is embarrassingly parallel and branch-light — the most reliable 10–100× Mojo migration in operations research and finance.

📌 k-Means Clustering (Lloyd's Algorithm)

assignment:  cᵢ = argminₖ ‖xᵢ − μₖ‖²   ·   update:  μₖ = (1/|Cₖ|) Σi∈Cₖ xᵢ   ·   cost per pass = O(n·k·d)
🐍 Python 
import numpy as np

def kmeans(X, k, iters=50, rng=None):
    n = len(X)
    mu = X[rng.choice(n, k, replace=False)]
    for _ in range(iters):
        d = ((X[:, None, :] - mu[None]) ** 2
             ).sum(-1)          # n × k distances
        c = d.argmin(1)
        for j in range(k):
            mu[j] = X[c == j].mean(0)
    return c, mu
🔥 Mojo 
def assign(X: Tensor[Float64], mu: Tensor[Float64])
          -> List[Int]:
    var n = X.dim(0)   # points
    var k = mu.dim(0)  # centroids
    var c = List[Int](capacity=n)
    # each point is independent — parallel-friendly
    for i in range(n):
        var best = 0
        var bd = inf
        for j in range(k):
            # squared distance ‖xᵢ − μⱼ‖² —
            # the SIMD dot-product kernel lives in here
            var d = sqdist(X, i, mu, j)
            if d < bd:
                bd = d; best = j
        c[i] = best     # nearest centroid wins
    return c

k-means is your first "real" migration candidate: pure arithmetic, no Python objects in the loop, and the distance kernel is exactly the dot-product code from the SIMD section.

🎒 Dynamic Programming: 0/1 Knapsack

recurrence:  T[i][w] = max( T[i−1][w],  vᵢ + T[i−1][w − wᵢ] )  if wᵢ ≤ w, else T[i−1][w]
memory trick:  one 1-D array updated right-to-left → O(W) instead of O(nW)
🐍 Python 
def knapsack(values, weights, W):
    dp = [0] * (W + 1)
    for v, w in zip(values, weights):
        for cap in range(W, w - 1, -1):
            dp[cap] = max(dp[cap],
                          v + dp[cap - w])
    return dp[W]

# portfolio/selection problems:
# values = expected returns, weights = budgets,
# W = total budget
🔥 Mojo 
def knapsack(values: List[Int],
             weights: List[Int],
             W: Int) -> Int:
    # dp[cap] = best value with budget 'cap'
    var dp = List[Int](W + 1, 0)
    for i in range(len(values)):
        var v = values[i]
        var w = weights[i]
        # right-to-left: keeps row i−1 intact
        @parameter
        for cap in range(W, w - 1, -1):
            dp[cap] = max(dp[cap],
                          v + dp[cap - w])
    return dp[W]

DP inner loops are branch-free and cache-sequential — ideal Mojo targets when W is large (millions of states). Watch the loop direction: it is the algorithm's core invariant, identical in both languages.

🗺️ Dijkstra Shortest Path

invariant:  when node u is popped with the smallest d(u), d(u) is final  (w ≥ 0)
relax:  if d(u) + w(u,v) < d(v):  d(v) ← d(u) + w(u,v)   ·   complexity: O((V + E) log V) with a binary heap
🐍 Python 
import heapq

def dijkstra(adj, s):
    n = len(adj)
    d = [float("inf")] * n
    d[s] = 0.0
    pq = [(0.0, s)]
    while pq:
        du, u = heapq.heappop(pq)
        if du > d[u]:
            continue          # stale entry
        for v, w in adj[u]:
            nd = du + w
            if nd < d[v]:
                d[v] = nd
                heapq.heappush(pq, (nd, v))
    return d
🔥 Mojo — flat CSR graph 
# CSR layout: edges sorted by source —
# sequential memory, no pointer chasing
#   offsets[v]   .. offsets[v+1]  = v's edges
#   edge_dst[e], edge_w[e]

def dijkstra(off: List[Int], dst: List[Int],
             w: List[Float64], s: Int)
             -> List[Float64]:
    var n = len(off) - 1
    var d = List[Float64](n, inf)  # best distance so far
    var pq = Heap[Float64, Int]()
    d[s] = 0.0
    pq.push(0.0, s)
    while pq.size() > 0:
        var (du, u) = pq.pop()      # smallest d(u) first
        if du > d[u]:
            continue                # stale entry, skip
        # relax every edge leaving u
        for e in range(off[u], off[u + 1]):
            var nd = du + w[e]
            if nd < d[dst[e]]:
                d[dst[e]] = nd
                pq.push(nd, dst[e])
    return d

The Mojo win here is the data layout, not the loop: CSR (compressed sparse row) turns linked structures into flat arrays that both cache lines and SIMD love. The same layout upgrade also speeds up the Python version via NumPy.

🛰️ Geomatics: NDVI & Slope/Aspect

NDVI = (NIR − R) / (NIR + R) ∈ [−1, 1]

Horn's method (3×3 window, cell size c):  ∂z/∂x = ((z₃ + 2z₆ + z₉) − (z₁ + 2z₄ + z₇)) / 8c,  ∂z/∂y = ((z₇ + 2z₈ + z₉) − (z₁ + 2z₂ + z₃)) / 8c

slope = atan( √( (∂z/∂x)² + (∂z/∂y)² ) ),   aspect = atan2(−∂z/∂y, ∂z/∂x)
🐍 Python (rasterio + NumPy) 
import numpy as np

def ndvi(nir, red):
    np.seterr(divide="ignore",
              invalid="ignore")
    out = (nir - red) / (nir + red)
    return np.nan_to_num(out, nan=0.0)

def horn_slope(z, c):
    dzdx = ((z[2:] + 2*z[1:-1, 2:]
             + z[:-2, 2:])
          - (z[2:] + 2*z[1:-1, :-2]
             + z[:-2, :-2])) / (8*c)
    # (analogously dzdy, then atan)
    return np.arctan(
        np.sqrt(dzdx**2 + dzdy**2))
🔥 Mojo — point-cloud transform kernel 
# WGS84 → local ENU, millions of points:
#   x = (λ − λ₀)·cos(φ₀)·R
#   y = (φ − φ₀)·R
#   z = h
def to_enu(lat: Tensor[Float64],
           lon: Tensor[Float64],
           h: Tensor[Float64], phi0: Float64,
           lam0: Float64, R: Float64)
           -> Tensor[Float64]:
    var n = lat.num_elements()
    var out = Tensor[Float64](n, 3)   # ENU triples
    comptime LANES = simdwidthof[DType.float64]()
    # pure arithmetic per point — no branches, no objects,
    # ideal for SIMD lanes and GPU dispatch (max.gpu)
    @parameter
    for i in range(n):
        var dphi = (lat[i] - phi0) * R       # north
        var dlam = (lon[i] - lam0) \
                   * cos(phi0) * R            # east
        out[i, 0] = dlam
        out[i, 1] = dphi
        out[i, 2] = h[i]                      # up
    return out

Pattern for geomatics: Python + GeoPandas/rasterio own I/O, CRS and maps; Mojo owns the per-cell and per-point arithmetic — NDVI, slope, convolution, and coordinate transforms over millions of elements.

🧠 AI: Autodiff Essentials

Every framework — PyTorch, JAX, Mojo — runs the same two equations. Know them and you can read any training loop.

forward:  zˡ = Wˡaˡ⁻¹ + bˡ,  aˡ = σ(zˡ)

backward (chain rule):  δᴸ = ∇ₐL ⊙ σ′(zᴸ),   δˡ = (Wˡ⁺¹ᵀ δˡ⁺¹) ⊙ σ′(zˡ)
gradients:  ∂L/∂Wˡ = δˡ (aˡ⁻¹)ᵀ,   ∂L/∂bˡ = δˡ
🐍 Python — autograd by hand on paper shape 
import numpy as np

def train_step(X, y, W1, b1, W2, b2, eta):
    # forward
    z1 = X @ W1 + b1
    a1 = np.maximum(z1, 0)          # ReLU
    z2 = a1 @ W2 + b2
    # MSE loss
    err = z2 - y
    # backward
    d2 = (2 / len(y)) * err
    gW2 = a1.T @ d2
    d1 = (d2 @ W2.T) * (z1 > 0)
    gW1 = X.T @ d1
    # SGD step
    W2 -= eta * gW2; W1 -= eta * gW1
    return W1, W2
🔥 Mojo — same graph, typed tensors 
def train_step(X: Tensor[Float64],
               y: Tensor[Float64],
               W1: Tensor[Float64],
               b1: Tensor[Float64],
               W2: Tensor[Float64],
               b2: Tensor[Float64],
               eta: Float64):
    # forward: z1 = X·W1 + b1 → ReLU → z2
    var z1 = matvec_bias(X, W1, b1)
    var a1 = relu(z1)
    var z2 = matvec_bias(a1, W2, b2)
    # backward: d2 = ∇ of MSE at the output
    var d2 = z2
    @parameter
    for i in range(d2.num_elements()):
        d2[i] = 2.0 * (z2[i] - y[i]) / M
    var gW2 = outer(a1, d2)          # ∂L/∂W2 = d2·a1ᵀ
    # chain rule one layer down, masked by ReLU grad
    var d1 = matvec_T(W2, d2)
    @parameter
    for i in range(d1.num_elements()):
        d1[i] *= relu_grad(z1[i])    # z1[i] > 0
    var gW1 = outer(X, d1)           # ∂L/∂W1 = d1·Xᵀ
    # SGD step: θ ← θ − η·∇J
    axpy(-eta, gW1, W1)
    axpy(-eta, gW2, W2)

Reading order: matmul → autodiff → training loop → GPU kernel. Each layer is built from the section before it. PyTorch in Python for research; this loop in Mojo when the same model must run fast in production.
